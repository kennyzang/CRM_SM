## 一、整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    测试用例 (*.spec.ts)                   │
│           FormTestBuilder API（唯一入口）                 │
└─────────────────────┬───────────────────────────────────┘
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
┌──────────────────┐   ┌──────────────────────┐
│  SchemaGenerator │   │   FillerFactory       │
│  DOM 探查生成     │   │   按 fdType 创建       │
│  JSON Schema     │   │   Filler 实例          │
└────────┬─────────┘   └──────────┬───────────┘
         │                        │
         ▼                        ▼
┌──────────────────┐   ┌──────────────────────────────────────┐
│  src/schemas/    │   │  Filler 组件（每种 fdType 一个类）      │
│  *.json          │   │  FdInputFiller / TextareaFiller /     │
│  （持久化）       │   │  RadioFiller / CheckboxFiller /       │
└──────────────────┘   │  SelectFiller / TimestampFiller /     │
                       │  TimepickerFiller / NumbertextFiller / │
                       │  MoneytextFiller                       │
                       └──────────────────────────────────────┘
```

## 二、核心模块

### FormTestBuilder（`src/core/FormTestBuilder.ts`）

测试用例的唯一入口，提供声明式 API：

| 方法 | 说明 |
|------|------|
| `initialize()` | 加载或生成 Schema；Schema 存在时直接加载，不重新探查 |
| `navigate()` | 导航到表单 URL，等待字段容器渲染完毕 |
| `fillAllFields()` | 遍历 Schema 所有字段，逐一调用对应 Filler 填充 |
| `fillRequiredFields()` | 仅填充 required=true 的字段 |
| `fillField(fieldId)` | 填充单个字段 |
| `submit()` | 在 `.ele-cru-layout-header` 内点击 Save/保存/提交按钮 |

### SchemaGenerator（`src/schema/SchemaGenerator.ts`）

一次性 DOM 探查，生成 JSON Schema 并持久化到 `src/schemas/{formId}.json`。

**关键设计：**
- 字段容器选择器：`.ele-xform-fieldset-wrap[data-id="{formId}.{fieldId}"]`
- fdType 检测：按 EasyCraft CRM 实际 fdType 字段值命名（见下表）
- radio/checkbox 选项提取：LUI 组件无 `for` 属性，通过 `ancestor::label[1]` + 末尾 span 获取文本

### FillerFactory（`src/filler/FillerFactory.ts`）

工厂模式，Map 注册 fdType → Filler 类。支持运行时动态注册新类型：

```typescript
FillerFactory.register('my_type', MyCustomFiller);
```

## 四、MKXFORM API 集成

### 4.1 核心方法

| API 名称 | 适用场景 | 说明 |
|---------|---------|------|
| `MKXFORM.setValue(fieldId, value)` | 主表 | 直接设置主表单字段值 |
| `MKXFORM.updateControl(fieldId, rowIndex, value)` | 明细表 | 设置明细表指定行字段值 |
| `MKXFORM.$(fieldId)` | 通用 | 获取组件实例 |
| `cmp._CURRENT_FIBRE.props` | 通用 | 获取组件属性对象 |

### 4.2 填充优先级

| 场景 | 优先方法 | 回退方法 |
|------|---------|---------|
| 主表 | `MKXFORM.setValue()` | `props.onChange()` → UI 交互 |
| 明细表 | `MKXFORM.updateControl()` | `props.onChange()` → UI 交互 |

### 4.3 字段标识格式

| 场景 | 格式 | 示例 |
|------|-----|-----|
| 主表字段 | `{formId}.{fieldId}` | `mk_model_xxx.fd_name` |
| 明细表字段 | `{detailTableId}.{fieldId}` | `mk_model_xxx_d_xxx.fd_name` |

## 五、Schema JSON 格式

```json
{
  "formId": "mk_model_20260425gq4b1",
  "formName": "KM Test Form",
  "url": "https://test.easycraft.ai/...",
  "fields": [
    {
      "id": "fd_radio",
      "fdType": "radio",
      "label": "单选框1",
      "required": false,
      "options": [
        { "label": "选项1", "value": "1" },
        { "label": "选项2", "value": "2" },
        { "label": "选项3", "value": "3" }
      ],
      "sourceComponent": "@elem/xform-radio",
      "methods": ["onChange"]
    },
    {
      "id": "fd_date",
      "fdType": "timestamp",
      "label": "日期1",
      "required": false,
      "placeholder": "Select the date",
      "sourceComponent": "@elem/xform-datetime",
      "methods": ["onChange"]
    },
    {
      "id": "fd_cfg",
      "fdType": "cfg",
      "label": "基础数据",
      "required": false,
      "cfgId": "123456",
      "sourceComponent": "@elem/xform-cfg",
      "methods": ["onChange"]
    }
  ],
  "generatedAt": "2026-05-04T00:00:00.000Z"
}
```

**字段属性说明：**

| 属性 | 类型 | 说明 |
|------|------|------|
| `id` | string | 字段 ID |
| `fdType` | string | 字段类型 |
| `label` | string | 字段标签 |
| `required` | boolean | 是否必填 |
| `options` | array | 选项列表（radio/checkbox/select） |
| `cfgId` | string | 基础数据 ID（cfg 类型） |
| `sourceComponent` | string | 源码组件标识（如 @elem/xform-input） |
| `methods` | array | 组件支持的方法列表 |

**注意事项：**
- `select` / `select~multi` 的 options 需手动维护（SchemaGenerator 不自动展开下拉捕获）
- Schema 文件可人工编辑，修改后直接生效，无需重新探查
- 重新探查会覆盖 Schema 文件，手动修改的内容将丢失

## 六、Schema 动态提取逻辑

### 6.1 源码组件提取

SchemaGenerator 优先从源码 JSON 的 `fdAttribute` 字段中提取组件信息：

```typescript
// fdAttribute 格式示例
{
  "fdAttribute": "{\"uuid\":\"fd_col_xxx\",\"config\":{\"key\":\"@elem/xform-input\"}}"
}
```

**提取优先级：**

| 优先级 | 提取位置 | 说明 |
|--------|---------|------|
| 1 | `attr.config.key` | 源码组件标识 |
| 2 | `attr.config.methods` | 组件方法列表 |
| 3 | `attr.methods` | 备用方法列表 |
| 4 | 映射表 | 兜底映射 |

### 6.2 基础数据配置提取

cfg 类型字段从 `fdAttribute` 或 `fdFontExtendData` 提取配置：

| 属性 | 来源 | 说明 |
|------|------|------|
| `cfgId` | `attr.cfgId` / `attr.fdId` / `attr.modelId` | 基础数据 ID |
| `cfgConfig` | `attr` | 完整配置对象 |

### 6.3 多环境路径适配

API 请求路径根据当前页面 URL 动态构造：

```typescript
// 判断是否为 mkpaas 环境
const isMkpaas = page.url().includes('/mkpaas/');
const basePaths = isMkpaas ? ['/mkpaas'] : ['', '/data'];
```

## 九、扩展新字段类型

1. 确认 CRM 的 `fdType` 字段值（从 API 返回的字段元数据中查看）
2. 创建 `src/filler/{FdType}Filler.ts`，继承 `BaseFiller`，实现 `fill()`
3. 在 `FillerFactory.ts` 中注册：`['fdType', MyFiller]`
4. 在 `SchemaGenerator.detectFieldType()` 中添加检测规则

---

## 十、已知限制

- **select/select~multi 选项**：SchemaGenerator 不自动展开下拉捕获选项，需手动维护 Schema
- **timestamp/timepicker**：readonly 输入框通过点击面板选择；非 readonly 时直接输入字符串
- **schema 自动生成**：依赖 `.ele-xform-fieldset-wrap` 选择器，若 CRM 升级改变该结构需同步更新
- **基础数据选项**：每次填充都从 API 获取最新数据，无缓存机制
