### Phase 0 探查结果（2026-07-08，已验证，非猜测）

**这份数据会随后台配置变动（人员调整、新开实体），不能只存一次静态快照，改为脚本化、可重复执行：**

- 脚本：`scripts/probe_sm_role_members.py`（脚本统一放项目规范的 `scripts/`；本文档及探查结果等 AI 产出物放收集箱 `AI输出/` 子目录，与人工原始资料 0-3.md / Role Definition.docx 区分开）
- 数据来源：真实接口（不是页面截图/UI 文案推测）
  - `POST /data/sys-right/sysRightGroup/get` → 权限组「Role users」具名成员
  - `POST /data/sys-modeling/sysModelingMain/data` → 线索池/公海池列表（含 `fd_pool_admin`）
- 认证：复用 `auth/auth-securemetric-crm*.json` 里 Playwright 保存的登录态（X-AUTH-TOKEN cookie）
- 用法：`python3 scripts/probe_sm_role_members.py soo`（也可传其他账号名，对应 `auth/auth-securemetric-crm-{账号}.json`）
- 输出：终端打印 + 落盘到 `doc/SM测试用例-收集箱/AI输出/role-members-snapshot.json`（每次重新运行会覆盖，代表"当前时刻"的真实配置，而不是写死的历史结论）

**注意（踩过的坑，供以后排查 401 用）**：`X-AUTH-TOKEN` 是 httpOnly cookie，会话有生命周期，`auth/*.json` 里存的 token 如果太久没跑过 Playwright 登录会失效（本次实测就遇到 401）。刷新方法：跑一次该账号的 Playwright 登录（走 `global-setup-securemetric-crm.ts` 或正常执行一条 spec 触发登录），session 文件会自动写入新 token；脚本不做自动登录，只负责读取已有登录态。

**最初手动核对时用的方式（一次性验证用，效率较低，仅作记录）**：逐个打开后台管理入口的两个页面用浏览器读——
1. 权限组编辑页（`sys-right/sysRightGroup/edit/...`）→ 角色下的「Role users」具名列表
2. 业务规则（线索池/公海池）列表页的「Admin / Administrator(s)」列
