### 测试分两条线：
1、完全都是我新建的，联系人、线索、商机一直到客户回款
1.1 在这个基础上，添加团队负责人，销售记录，任务
1.2 导出报价表

2、普通销售视角：线索退回，更换负责人、商机推进

3、管理员视角：线索分配，客户分配、线索收回、客户收回

## 能想到的用例
### 联系人

联系人添加团队 - 团队成员在我参与的可以看到这条数据

### 线索
* 新建线索
* 线索推进
* 线索添加团队 - 团队成员在我参与的可以看到这条数据
* 线索阶段推进：阶段推进，推进器当前值变化，赢率为5%；转换按钮出现
* 线索转换：填写必填信息；转换后查看客户、联系人、商机信息
    * 新建客户：客户名称、注册码不能重复；这里是一个测试点；团队成员带过来、销售记录带过来
    * 已有客户：团队成员带过来、销售记录带过来
    * 联系人：团队成员带过来，销售记录和销售记录中客户的拜访人有关
    * 商机：团队成员带过来、销售记录带过来；有源线索；线索的产品可以传递到商机、商机可以变更
* 销售阶段重置：阶段推进后，如果误操作，或者赢率没有更新，可以点击阶段重置
* 线索转换后：原来的线索锁定了，不能再转换和编辑，很多操作也对于对应取消
* 线索选项卡：Activity History、Contact、Contact、Related Leads、Conversion History
* 线索下新建销售记录：Contact 当前线索联系人；刷新后线索留存；转换后根据配置决定了是否在客户、商机、联系人中显示
* 按钮测试：跟进、退回、无效、转移、更换负责人、归集、重置商机推进（用户手册有，这里是根据实际情况探查的，我们需要记录来源，接口请求 - 看详情页有哪些按钮，他们的显示条件；按钮的权限 主要是两个）
* 线索下新建任务

-- 主线应该是新建、推进、销售记录

#### 线索转换
线索转换后通用变化：线索状态变更为已转换，按钮只有解锁和打印（当前线索处于锁定状态）过程记录+1；商机+1；线索转换记录+1；
- 客户的页签：线索+1；商机+1；可以对应跳转
新客户：客户列表新增，和我们转换的客户名称、注册码、客户类型；
老客户：团队、销售记录根据配置是否带过来，这里是更新；公海池，假如原来客户不在公海池，转换后会进入公海池
联系人：团队

### 线索池更换负责人

**设计器表单字段**（弹窗内）：
| 字段 | 控件 | 选项 |
|------|------|------|
| 将负责人更换为 | 地址本(人员选择) | 选人 |
| 将原负责人 | 单选框 | 移出团队 / 变更为团队成员 |
| 团队角色 | 下拉框 | 普通成员 |
| 权限 | 下拉框 | 只读 / 读写 |
| 将原团队普通成员 | 单选框 | 清空 / 保留 |
| 线索池ID | 输入 | - |
| 线索领取上限 | 输入 | - |

> 很多操作涉及弹窗交互，详细的弹窗字段操作步骤见 `AI输出/基础功能用例/zh/线索-转换-池.yaml`
