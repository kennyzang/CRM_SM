## 1. Module Overview

The **Payment Schedule** module tracks the accounts receivable (A/R) milestones for each Sales Order. Payment Schedule records are **automatically generated by the system** from the Sales Order — there is no manual "Create" form. Users interact with this module primarily to monitor collection progress, review receivable breakdowns, and trigger invoice applications.

Payment Schedule IDs follow the format: `PP` + `YYYYMMDD` + sequence number (e.g., `PP202604270002`).

### 1.1 Entry Points

| Entry Point | Path |
|-------------|------|
| Standalone list | Left sidebar → **REVENUE** → **Payment Schedule** |
| From Sales Order | Sales Order Details → **Payment Schedule** tab |

### 1.2 Core Functions

- Track receivable milestones (Down Payment, Progress Payment, Final Payment)
- Monitor completion percentage updated by the Project Manager (PM)
- Provide the Account Manager (AM) with signals to generate Invoice Applications
- Summarise invoiced, uninvoiced, and outstanding amounts per milestone
- Aggregate revenue data for reporting

## 2. List View

The Payment Schedule list shows all A/R milestones accessible to the current user.

| Column | Description |
|--------|-------------|
| Payment Schedule ID | System-generated ID (`PP` + date + sequence) |
| Sales Order ID | Linked Sales Order (clickable link) |
| Sales Rep | Account Manager assigned to the SO |
| Payment Status | Current collection status (badge indicator) |
| Completion % | Project completion percentage (updated by PM) |
| Payment Type | Down Payment / Progress Payment / Final Payment |
| Receivable % | Percentage of total SO value due at this milestone |
| Receivable Amount | Absolute currency amount due |
| Amount Received | Amount already collected |
| Amount Uncollected | Outstanding balance for this milestone |

### Tab Filters

The list view offers tab-based filters at the top:

| Tab | Description |
|-----|-------------|
| All | All Payment Schedule records |
| Total A/R Amount | Filter: total receivable amount view |
| Repaid Amount | Filter: amounts already collected |
| Total Outstanding A/R Amount | Filter: focus on uncollected balances |

## 3. Viewing a Payment Schedule

Since Payment Schedules are system-generated, the primary user action is **viewing and monitoring**.

### 3.1 From the Sales Order

1. Open the relevant Sales Order.
2. Navigate to the **Payment Schedule** tab.
3. All milestone records for this SO are listed here, showing each payment type, amount, and status.

### 3.2 From the Standalone List

1. Navigate to Left sidebar → **REVENUE** → **Payment Schedule**.
2. Use the search bar to find by Sales Order ID, Customer, or Payment Schedule ID.
3. Click on a row to open the detail view for that milestone.

## 5. Business Rules & Workflow

### 5.1 Auto-generation from Sales Order

Payment Schedules are created **automatically** when a Sales Order is confirmed. The system generates one record per payment milestone defined in the SO's payment terms. Users do not fill a creation form.

### 5.2 Typical Payment Structure (50/50 Split)

The most common payment structure at Securemetric is a **50/50 split**:

| Milestone | Payment Type | % of SO Value |
|-----------|-------------|---------------|
| Upon PO / contract signing | Down Payment | 50% |
| Upon delivery / project completion | Progress Payment or Final Payment | 50% |

Some projects use a three-way split (e.g., 30% Down / 40% Progress / 30% Final), depending on the contract terms.

### 5.3 Completion % Updated by PM

The **Completion %** field is maintained by the **Project Manager (PM)**, not the Account Manager. It reflects the actual progress of project delivery or service fulfilment:
- 0% = project not started
- 50% = midpoint milestone reached
- 100% = project/service fully delivered

### 5.4 Invoice Application Triggered at 100%

When the PM updates Completion % to **100%**, this signals the Account Manager (AM) to generate an **Invoice Application** for that milestone. The AM reviews the billing detail and submits the invoice application to Finance.

### 5.5 Revenue Split by Product Category

For milestones with mixed product categories (e.g., hardware + software + services), the receivable amount may be split across categories. Each sub-category is tracked separately in the Billing Detail sub-tab.

### 5.6 Payment Status Badge

| Status | Meaning |
|--------|---------|
| Pending | Invoice not yet issued |
| Invoiced | Invoice issued, payment not yet received |
| Partially Paid | Some payment received, balance outstanding |
| Paid | Full milestone amount collected |

## 6. FAQ & Notes

**Q: I need to create a Payment Schedule for a new SO. How do I do it?**
You don't create Payment Schedules manually. They are auto-generated when the Sales Order is confirmed. If a milestone is missing, check whether the SO's payment terms were configured correctly. Contact your system administrator if needed.

**Q: The Completion % is still 0% but the project has started. Who updates it?**
The **Project Manager (PM)** is responsible for updating Completion %. Contact the PM assigned to the project and request an update.

**Q: The Amount Received is wrong. Can I edit a Payment Schedule record?**
Payment Schedule records are derived and cannot be directly edited in the main fields. Payment amounts are updated via Collection records. Check the **Payment Detail** sub-tab to see what collection records are linked.

**Q: Why is "Uninvoiced Amount" showing a positive value even though I raised an invoice?**
The invoice may not yet be linked to this Payment Schedule milestone. Check the **Billing Detail** sub-tab and confirm the invoice is properly associated.

**Q: Can one Payment Schedule milestone span multiple invoices?**
Yes. A single milestone may be billed in multiple invoices (e.g., partial billing). Each invoice appears as a separate row in the **Billing Detail** sub-tab.

**Q: How do I identify which Payment Schedules are overdue?**
Use the **Total Outstanding A/R Amount** tab filter in the list view to see all milestones with uncollected balances. Cross-reference the expected collection dates from the linked SO payment terms.

**Q: The Payment Schedule ID is `PP202604270002`. What does that mean?**
- `PP` = Payment Plan prefix
- `20260427` = creation date (2026-04-27)
- `0002` = the second record created on that date
