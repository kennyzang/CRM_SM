## 1. 模块概述

**发货（Delivery）** 模块用于追踪与销售订单相关的实物货物发运及物流交接事件。当货物或设备发往客户时，发货记录将捕获所有快递、运输成本、空运单及重量信息。该模块作为履约的运营记录，与付款计划中的财务追踪相互独立。

### 1.1 入口

| 入口 | 路径 |
|------|------|
| 独立列表 | 左侧导航 → **销售订单（SALES ORDER）** → **发货（Delivery）** |

### 1.2 核心功能

- 将货运与来源销售订单关联
- 记录快递公司信息（公司名称、空运单号、重量）
- 追踪以马来西亚林吉特（MYR）计的运费和燃油附加费
- 记录形式发票（PI）编号及客户自提参考信息
- 记录负责发货和完成交付的人员
- 将发票编号与货运关联

## 3. 创建发货记录

### 3.1 打开表单

进入左侧导航 → **销售订单（SALES ORDER）** → **发货（Delivery）**，点击 **+ 新建**。

### 3.2 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 销售订单号 | 是 | 关联查找 | 选择关联的销售订单 |
| 日期 | 否 | 日期/时间选择器 | 发货记录创建或发货事件的日期 |
| PI 编号 | 否 | 文本输入 | 本次货运签发的形式发票编号 |
| 自提编号 | 否 | 文本输入 | 客户自行取货时的参考编号 |
| 客户名称 | 否（自动） | 只读文本 | 从关联销售订单自动填充 |
| 销售人员 | 否 | 地址选择器（用户） | 负责该订单的客户经理或销售代表 |
| 物品描述 | 否 | 多行文本 | 发运货物的描述说明 |
| 发票编号 | 否 | 文本输入 | 与本次货运关联的商业发票编号 |
| 完成人 | 否 | 地址选择器（用户） | 实际完成交付或移交的工作人员 |
| 发货日期 | 否 | 日期/时间选择器 | 货物实际离开仓库或办公室的日期和时间 |
| 快递公司 | 否 | 文本输入 | 快递公司名称（如 DHL、FedEx、Pos Laju） |
| 燃油附加费（MYR） | 否 | 金额输入（MYR） | 快递公司收取的燃油附加费，以马来西亚林吉特计 |
| 空运单号 | 否 | 文本输入 | 快递公司提供的空运单（AWB）或追踪编号 |
| 重量 | 否 | 数字输入 | 货物重量（千克或适用单位） |
| 快递发票编号 | 否 | 文本输入 | 快递公司签发的发票编号 |
| 运费（MYR） | 否 | 金额输入（MYR） | 快递公司收取的总运费，以马来西亚林吉特计 |
| 备注 | 否 | 多行文本 | 关于货运的补充说明 |
| 实体代码 | 否 | 文本输入 | 多实体运营中的内部实体或子公司代码 |

### 3.3 保存

点击顶部操作栏中的 **保存**。发货记录保存成功并与销售订单关联，客户名称自动填充，无法直接编辑。

## 5. 业务规则与流程

### 5.1 标准发货流程

```
销售订单已确认 → 货物备好待发
→ 创建发货记录 → 选择销售订单号
→ 客户名称自动填充
→ 填写快递信息（快递公司、空运单号、重量、发货日期）
→ 填写费用信息（运费 MYR、燃油附加费 MYR）
→ 填写 PI 编号和发票编号
→ 指定完成人
→ 保存
```

### 5.2 销售订单为必填关联

每条发货记录**必须关联至一个销售订单**。销售订单决定客户名称的来源。发货记录无法独立创建，必须追溯至一个已确认的销售记录。

### 5.3 客户名称自动填充

选择销售订单后，**客户名称**字段将从销售订单记录中自动填充，为只读字段，无法覆盖。若出现错误的客户名称，说明选择了错误的销售订单，请更正关联的销售订单。

### 5.4 运费以马来西亚林吉特（MYR）计

**运费（MYR）** 和**燃油附加费（MYR）** 均以马来西亚林吉特记录，无论发票货币为何。这是内部成本追踪和报销的需要。外币运费请按当时汇率换算为马来西亚林吉特后再填入。

### 5.5 客户自提货物

若客户自行安排取货（自提），请在**自提编号**字段填写客户或物流协调人员提供的参考编号。自提记录中，快递公司、空运单号和重量字段可留空。

### 5.6 PI 编号与发票编号的区别

| 字段 | 用途 |
|------|------|
| PI 编号 | 形式发票编号——发货前签发，用于报关/付款参考 |
| 发票编号 | 商业/税务发票编号——发货后签发，用于账单开具 |

同一次货运可能同时涉及两者，请根据创建记录时已签发的文件填写相应字段。

### 5.7 实体代码

**实体代码**标识负责本次货运的 Securemetric 集团内哪家子公司或业务实体。这对多实体运营（如马来西亚实体代表区域实体发货）非常重要。如不确定应使用哪个代码，请咨询上级。

## 6. 常见问题与注意事项

**问：我需要的销售订单在查找下拉列表中找不到，原因是什么？**
该销售订单可能处于不允许创建发货记录的状态，或您没有该销售订单的查看权限。请检查销售订单状态和您的访问权限，如有需要请联系上级。

**问：货物还未实际发出，可以提前创建发货记录吗？**
可以。**日期**字段记录创建记录的时间，**发货日期**字段记录货物实际出库的时间。可提前创建记录，待货物发出后再填写发货日期。

**问：快递公司开了一张涵盖多个货运的合并发票，如何记录？**
为每次货运分别创建一条发货记录，分别关联至各自的销售订单，在各记录中填写相同的**快递发票编号**。总费用可能需要手动按比例分摊至各记录。

**问：客户自提的情况下也需要创建发货记录吗？**
是的，需要创建发货记录并填写**自提编号**，快递相关字段（空运单号、快递公司、重量）可留空。这确保履约事件在 CRM 中有记录存档。

**问："完成人"应填写谁？**
应填写实际交付货物、签署交货单或与快递公司确认交接的人员。根据业务流程，可能是仓库员工、物流协调员或销售代表。

**问：可以在发货记录中附上快递的送货确认文件吗？**
请检查您的 CRM 配置中发货表单是否包含附件字段。若没有，可将文件上传至关联销售订单的附件区，并在备注字段中注明参考信息。

**问："实体代码"字段有什么用途？**
用于标识 Securemetric 集团内哪家法律实体（子公司）负责本次货运，主要用于集团内部结算和合规报告。请向财务或运营团队咨询正确的代码。
