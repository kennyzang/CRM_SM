## 1. 模块概述

**客户（Customer）** 模块是 Securemetric CRM 的核心实体，用于管理所有与公司有业务往来的组织或企业，分为**终端客户（End Customer）**（直接采购方）和**合作伙伴（Partner）**（经销商、分销商、系统集成商）。

所有下游业务单据——商机、报价单、销售订单、合同、收款——均与客户记录相关联。

### 1.1 入口

| 入口 | 路径 |
|------|------|
| 主入口 | 左侧导航 → **客户（Customer）** | [直达链接](http://172.18.114.231:8088/web/#/current/sys-modeling/app/km-ltc/listView/1hvp2b0bjw4vw6he8wg8l6lj3eo66ob102w1/1i1oh7vniw66w11k1w225fbfk1c7gcpr6aw1?type=list&navId=1hvp21k7lw4vw6h64w37pp9dm27vj66f3cw1){: target="_blank" rel="noopener"} |
| 新建表单 | 左侧导航 → 客户 → **+ 新建**（或直接访问新建 URL） |

### 1.2 核心功能

- 维护所有业务账户（终端客户与合作伙伴）的主记录
- 追踪客户归属及协同跟进人（多位销售代表）
- 存储多国运营的地址信息（MY / VN / PH / ID）
- 作为整个销售流程的根节点锚点

### 1.3 客户状态

客户有两个独立的状态维度：

**成交状态**

| 状态 | 说明 |
|------|------|
| 未成交 | 尚未产生合同/订单 |
| 已成交 | 客户下有商机赢单，或已确认销售订单/合同 |
| 多次成交 | 与该客户已发生多次成交记录 |

**分配状态**

| 状态 | 说明 |
|------|------|
| 未分配 | 客户位于公海中，尚无负责人 |
| 已分配 | 客户已有负责人，由其跟进 |

### 1.4 客户生命周期

```
线索转换 / 手工新建
        ↓
   [已分配] 销售跟进
        ↓
   主动退回 / 超时收回
        ↓
   [未分配] 进入公海
        ↓
   领取 / 分配
        ↓
   [已分配] 继续跟进 → 成交
```

## 2. 列表视图

主要列说明如下：

| 列名 | 说明 |
|------|------|
| 客户名称 | 主要标识，点击进入详情 |
| 客户类型 | 终端客户或合作伙伴 |
| 客户来源 | 客户获取渠道 |
| 法人注册码 | 唯一注册编号 |
| 电话 | 主要联系电话 |
| 负责人 | 指定的销售代表 |

![客户列表视图](../../assets/customer-list-001.png)

### 2.1 视图场景

| 场景标签 | 显示范围 |
|----------|---------|
| 我负责的 | 当前用户为负责人的客户 |
| 我下属负责的 | 当前用户为部门主管时，其下属负责的客户 |

- 使用顶部搜索栏按客户名称或法人注册码筛选。

- **我的客户**开关可将列表限定为当前用户负责或协同跟进的记录。

## 3. 创建客户

### 3.1 打开表单

在客户列表页点击 **+ 新建**，或直接访问新建 URL。

![客户创建表单](../../assets/customer-create-001.png)

### 3.2 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 客户名称 | 是 | 文本输入 | 完整法定名称或商用名称 |
| 法人注册码 | 是 | 文本输入 | 系统全局唯一，不可重复 |
| 客户类型 | 否 | 级联下拉 | 终端客户 / 合作伙伴；影响子类型选项 |
| 客户来源 | 否 | 级联下拉 | 客户引入方式 |
| 电话 | 否 | 文本输入 | 主要联系电话 |
| 邮件 | 否 | 文本输入 | 主要电子邮件地址 |
| 业务范围 | 否 | 多行文本 | 简要描述客户的业务领域 |
| 负责人 | 否 | 地址选择器 | 默认为当前登录用户 |
| 协同跟进人 | 否 | 多选用户选择器 | 可同时跟进该客户的其他销售代表 |

### 3.3 保存

点击顶部操作栏中的 **保存**。系统自动分配唯一客户 ID 并跳转至列表页。

## 5. 业务操作

### 5.1 详情页操作按钮

详情页右上角按钮根据当前用户角色和客户分配状态动态显示；超出固定数量时自动折叠到 **"更多"** 下拉菜单。

#### 通用操作

| 按钮 | 说明 | 显示条件 |
|------|------|----------|
| 打印（Print） | 打印客户详情 | 始终显示 |
| 编辑（Edit） | 编辑客户字段 | 始终显示 |

#### 负责人操作

| 按钮 | 说明 | 显示条件 |
|------|------|----------|
| 退回（Return） | 将客户退回公海 | 当前用户为负责人，且分配状态=【已分配】 |
| 建任务（Create Job Task） | 创建跟进任务并设置截止日期和提醒 | 分配状态=【已分配】 |
| 客户名称变更（Change Name） | 修改客户名称 | 当前用户为负责人 |
| 客户流失（Customer Lost） | 将客户标记为流失 | 当前用户为负责人，且客户生命周期不处于【流失客户】阶段 |

#### 公海操作

| 按钮 | 说明 | 显示条件 |
|------|------|----------|
| 领取（Claim） | 认领未分配客户为自己负责 | 分配状态=【未分配】，当前用户为公海成员，且公海规则允许成员自领 |
| 分配（Assign） | 将客户指派给指定销售代表 | 分配状态=【未分配】，当前用户为公海管理员 |
| 收回（Reclaim） | 强制将已分配客户收回公海 | 分配状态=【已分配】，当前用户为公海管理员 |
| 转移（Transfer） | 将客户移至其他公海 | 当前用户为公海管理员，且公海规则允许转移；无公海时始终显示 |
| 变更负责人（Change Owner） | 更换客户当前负责人 | 客户有公海、有负责人，且公海规则允许变更负责人 |
| 合并（Merge） | 将当前客户合并为另一客户的子客户 | 无公海时始终显示；有公海时需当前用户为公海管理员 |

### 5.2 退回公海

将已分配的客户主动退回公海，供其他销售代表认领。适用于长期无进展或已确定输单的情况。

> **前提**：当前用户为该客户的负责人，且客户分配状态为【已分配】

**操作路径**：客户详情页右上角 → **退回（Return）**

- 退回时需选择**退回原因**。
- 若该客户不属于任何公海，需先选择目标公海再退回。
- 退回后客户进入所属公海的【未分配】队列，负责人和协同跟进人同步清空。

### 5.3 公海操作

公海是管理未分配客户资源的共享池，支持以下操作：

| 操作 | 说明 | 前提 |
|------|------|------|
| **领取（Claim）** | 将未分配客户认领为自己负责 | 当前用户为公海成员，分配状态=【未分配】，且公海规则允许成员自领 |
| **分配（Assign）** | 将客户指派给指定销售代表 | 当前用户为公海管理员，分配状态=【未分配】 |
| **收回（Reclaim）** | 强制将已分配客户收回公海 | 当前用户为公海管理员，分配状态=【已分配】 |
| **转移（Transfer）** | 将客户从当前公海移至其他公海 | 当前用户为公海管理员，且公海规则允许转移；无公海时始终可用 |
| **变更负责人（Change Owner）** | 更换客户当前负责人 | 客户有公海、有负责人，且公海规则启用了"允许变更负责人" |

**操作路径**：客户详情页右上角 → 对应操作按钮

> **持有量限制**：若当前用户的客户持有量已达上限，**领取**和**新建**操作均会被阻止。请联系公海管理员调整限额或先退回现有客户。

### 5.4 建任务

为客户创建跟进任务，设置截止日期和提醒，便于按时推进客户跟进。

> **前提**：客户分配状态为【已分配】

**操作路径**：客户详情页右上角 → **建任务（Create Job Task）**

### 5.5 合并客户

将当前客户合并为另一客户的子客户，用于处理重复记录或组织架构调整。

> **前提**：客户无公海时始终可用；有公海时需当前用户为公海管理员

**操作路径**：客户详情页右上角 → **合并（Merge）**

- 合并后，当前客户成为目标客户的**下级客户**，可在目标客户详情页"下级客户"选项卡中查看。
- 合并前请仔细确认，合并操作不可撤销。

### 5.6 客户名称变更

修改客户的法定名称或商用名称，记录变更历史。

> **前提**：当前用户为该客户的负责人

**操作路径**：客户详情页右上角 → **客户名称变更（Change Name）**

### 5.7 客户流失

将客户标记为流失状态，触发客户生命周期流转至【流失客户（Lost）】阶段。

> **前提**：当前用户为该客户的负责人，且客户生命周期尚未处于【流失客户】阶段

**操作路径**：客户详情页右上角 → **客户流失（Customer Lost）**

**客户生命周期阶段**（由动作流自动触发）：

| 阶段 | 说明 |
|------|------|
| 潜在客户（Potential） | 尚未正式签约或达成交易 |
| 签约客户（Contracted） | 已签订合同 |
| 正式客户（Official） | 正式合作关系建立 |
| 活跃客户（Active） | 持续有活跃业务往来 |
| 忠诚客户（Loyal） | 长期稳定合作 |
| 沉默客户（Dormant） | 长时间无活跃互动 |
| 流失客户（Lost） | 客户已流失，标记后按钮不再显示 |

### 5.8 客户声音

记录与客户沟通过程中收集到的反馈、建议或诉求，便于团队后续跟进。

**操作路径**：客户详情页 → 客户声音 → **新建**

### 5.9 联合跟进人

允许多名销售成员协同服务同一客户，适用于大客户或复杂项目场景。联合跟进人可查看并编辑客户记录（受角色权限控制），并接收相关通知。

> **前提**：当前用户为公海成员，且拥有客户联合跟进权限

**操作路径**：CRM 导航菜单 → [**客户联合跟进**](http://172.18.114.231:8088/web/#/current/sys-modeling/app/km-ltc/listView/1igbbd2e4waswpc3twrlj022omb6g52lghw1/1igb3or39waswp7tvw3t9sn0rtepunb25pw1?type=list&navId=1hvp21k7lw4vw6h64w37pp9dm27vj66f3cw1){: target="_blank" rel="noopener"} → **新建**

- 联合跟进支持审批流程，审批通过后申请人自动成为该客户相关团队的联合跟进人。
- 联合跟进人与**协同跟进人**不同：协同跟进人在新建/编辑客户时直接填写；联合跟进人通过独立申请流程添加。

## 6. 业务规则与流程

### 6.1 法人注册码唯一性

法人注册码字段强制执行**全系统唯一**约束。若保存时发现编码已被占用，系统将显示验证错误。请在新建前先行核查，避免重复创建。

### 6.2 客户查重

新建客户时系统默认以**客户名称**为查重标识，发现重复时不可保存。可通过"查重工具"预先检索系统内是否已有同名客户。

### 6.3 客户持有量上限

管理员可为每位销售代表设置**客户持有量上限**。达到上限后，该用户无法新建客户，也无法从公海领取客户，直到其当前持有量降低。如遇此情况，请联系公海管理员调整配额。

### 6.4 非活跃客户自动归还公海

每个公海可配置**超时收回规则**：

| 规则类型 | 触发条件 |
|----------|---------|
| 未跟进收回 | 超过设定天数未产生任何跟进记录 |
| 未成交收回 | 超过设定天数仍未成交 |

触发后客户自动归还至公海，负责人和协同跟进人同步清空。请定期跟进，防止客户被意外回收。

### 6.5 协同跟进人

**协同跟进人**在新建或编辑客户时直接填写，与通过独立申请流程添加的**联合跟进人**不同（见§5.5）。协同跟进人可查看、编辑客户记录（受角色权限控制）。

### 6.6 客户类型：终端客户 vs 合作伙伴

| 类型 | 说明 |
|------|------|
| 终端客户（End Customer） | 直接使用或采购 Securemetric 产品/服务的组织 |
| 合作伙伴（Partner） | 代表 Securemetric 进行销售的经销商、分销商或系统集成商 |

客户类型驱动级联子类型选项。请在创建时选择正确类型，后期修改可能影响流水线报告。

## 7. 常见问题与注意事项

**问：保存时提示"法人注册码已存在"，该怎么办？**
在客户列表中搜索该注册码，确认是否已有记录。若该记录属于其他负责人，请联系上级或通过公海池认领流程处理。切勿创建重复记录。

**问：一个客户可以有多个负责人吗？**
**负责人**只能有一位，但可以添加多个**协同跟进人**。协同跟进人与负责人享有相同的查看和编辑权限。如需正式多人协同，可通过"联合跟进人"申请流程处理。
