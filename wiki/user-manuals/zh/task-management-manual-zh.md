## 1. 模块概述

**任务管理（Task Management）** 模块允许团队成员在任意 CRM 实体中创建、分配和追踪任务。任务必须关联父记录（通常为商机、线索、客户或联系人），并遵循从创建到执行再到确认的结构化生命周期。对于需要正式委派和接收确认的场景，可使用**任务令**功能。

### 1.1 入口

| 入口 | 路径 |
|------|------|
| 从商机进入 | 商机详情 → 任务区域（右侧边栏或选项卡）→ **新建任务** | [直达链接](http://172.18.114.231:8088/web/#/current/sys-modeling/app/km-ltc/listView/1inl12detwehw1ogaow3es4jf12qd3jmlvw1/1imh2voajwe8w5q66w23kb5k33rcjo1p2tw1?type=list&navId=1hvp21k7lw4vw6h64w37pp9dm27vj66f3cw1){: target="_blank" rel="noopener"} |
| 从线索进入 | 线索详情 → 任务区域 → **新建任务** |
| 从客户进入 | 客户详情 → 任务区域 → **新建任务** |
| 从联系人进入 | 联系人详情 → 任务区域 → **新建任务** |
| 任务列表页 | 左侧导航 → **ACTIVITY → Tasks** |
| 任务令 | 左侧导航 → **ACTIVITY → Task Order** |

### 1.2 核心功能

- 将行动项分配给指定团队成员（执行人）
- 通过反馈与确认流程追踪任务进度
- 设置基于截止时间的提醒（待办事项 + 邮件）
- 将复杂任务拆解为子任务
- 通过抄送人让相关方保持知情
- 使用任务令进行正式委派，要求执行人明确接收确认

### 1.3 任务生命周期

```
负责人创建任务 → 执行人收到待办事项 + 邮件通知
  → 执行人完成工作并提交反馈（进度百分比）
  → 任务状态变为"待确认"
  → 负责人审核后点击"通过"
  → 任务状态变为"已完成"（100%）
```

## 2. 创建任务

### 2.1 打开任务表单

1. 进入任意详情页（商机、线索、客户或联系人）。
2. 找到右侧边栏或选项卡区域的**任务**面板。
3. 点击**新建任务**。

任务表单打开后，**关联类型**和**关联数据**字段已根据父记录自动填充。

### 2.2 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 截止日期 | 是 | 日期/时间选择器 | 任务必须完成的时间 |
| 负责人 | 是 | 用户标签 | 自动填充为当前用户；负责审核和确认任务完成的人员 |
| 执行人 | 是 | 用户标签 | 执行任务工作的人员 |
| 优先级 | 是 | 下拉选择 | 高 / 次要 / 低 |
| 关联类型 | 是（自动） | 下拉选择 | 自动填充为父实体类型（如"商机"） |
| 关联数据 | 是（自动） | 只读查找 | 自动填充为父记录名称 |
| 抄送人 | 否 | 用户标签 | 需要接收通知但无需采取行动的人员 |
| 描述 | 否 | 多行文本 | 给执行人的详细说明 |
| 上级任务 | 否（自动） | 只读 | 若为子任务则显示父任务；否则显示"-" |
| 附件 | 否 | 文件上传 | 提供给执行人的参考文件 |

### 2.3 提醒配置

表单底部为**提醒**子表，每行定义一条提醒规则。

| 列名 | 类型 | 选项 | 默认值 |
|------|------|------|--------|
| 序号 | 自动 | — | 1 |
| 提醒时间 | 下拉选择 | 提前 1 天 / 提前 3 小时 / 提前 1 小时 / 提前 30 分钟 / 提前 15 分钟 / 到期时 | 提前 1 天 |
| 方式 | 复选框 | 待办事项、邮件 | 两者均勾选 |

- **待办事项**：在 CRM 内为接收人创建一条待办事项。
- **邮件**：向接收人发送邮件通知。
- 点击**插入**或**复制**可添加多行提醒（例如同时设置提前 1 天和提前 3 小时的提醒）。

![任务创建表单——截止日期、负责人、执行人、优先级、提醒子表等全部字段](../../assets/task-001.jpg)

### 2.4 保存任务

点击**保存**。任务创建后，执行人将收到：
1. CRM 内的**待办事项**（To-Do）。
2. **邮件通知**（若在提醒子表中勾选了邮件方式）。

任务出现在父记录的任务列表中。

![父记录中的任务列表——展示任务条目、状态、优先级与执行人](../../assets/task-004.jpg)

## 3. 任务详情视图

### 3.1 头部信息

| 字段 | 说明 |
|------|------|
| 任务标题 | 任务名称（带星标/收藏图标） |
| 状态 | 徽章：**进行中**（蓝色）/ **待确认** / **已完成**（绿色） |
| 优先级 | 徽章：**高** / **次要** / **低** |
| 创建时间 | 相对时间（如"今天 23:43"） |
| 负责人 | 负责确认任务的用户姓名 |

![任务详情页——状态徽章、优先级、基本信息选项卡与进度条](../../assets/task-002.jpg)

### 3.2 选项卡

| 选项卡 | 内容 |
|--------|------|
| 基本信息 | 截止日期、执行人、抄送人、关联记录、提醒、进度条、描述、附件、子任务 |
| 执行历史 | 按状态筛选的任务记录：进行中 / 已完成 / 待确认 |
| 任务反馈 | 执行人所有反馈提交的时间线 |

### 3.3 基本信息字段

| 字段 | 说明 |
|------|------|
| 截止日期 | 近期截止时显示相对时间（如"明天 23:41"） |
| 执行人 | 用户头像 + 姓名；副文本显示"N 个进行中 · N 个已完成" |
| 抄送人 | 无抄送人时显示"无" |
| 关联记录 | 可点击的父记录链接 |
| 提醒 | 已配置提醒规则的摘要 |
| 进度 | 可视化进度条（0% → 100%），通过任务反馈更新 |
| 描述 | 创建时填写的任务说明 |
| 附件 | 已上传文件列表，或显示"无" |
| 子任务 | **+ 添加子任务**按钮，用于拆分复杂任务 |

### 3.4 操作按钮

| 按钮 | 用途 |
|------|------|
| 编辑（铅笔图标） | 修改任务详情（截止日期、执行人、提醒等） |
| 删除（垃圾桶图标） | 永久删除任务 |
| 展开 | 全屏查看任务 |
| 关闭（X） | 返回父记录 |
| 任务完成 | 标记任务为完成（仅负责人可操作；使用后置灰） |

任务可从多个入口查看，适合不同使用场景。

### 4.1 从父记录查看

在商机、线索、客户或联系人的详情页，右侧边栏或任务选项卡展示与该记录关联的所有任务。

| 列名 | 说明 |
|------|------|
| 任务标题 | 点击进入任务详情 |
| 状态 | 进行中 / 待确认 / 已完成 |
| 优先级 | 高 / 次要 / 低 |
| 执行人 | 头像 + 姓名 |
| 截止日期 | 日期，临近时变红 |

### 4.2 从待办事项查看

顶部导航栏铃铛图标（或**待办事项**面板）汇总显示当前用户作为**负责人**或**执行人**的所有任务，按截止日期排序。适合快速了解当前任务优先级。

### 4.3 任务列表页

**操作路径**：左侧导航 → **ACTIVITY → Tasks**

任务列表页汇总显示当前用户可访问的所有任务，支持多维度筛选和排序。

**筛选选项**：

| 筛选维度 | 可选项 |

| 状态 | 进行中 / 待确认 / 已完成 |
| 优先级 | 高 / 次要 / 低 |
| 截止日期 | 日期范围 |
| 执行人 | 用户选择器 |
| 关联记录类型 | 商机 / 线索 / 客户 / 联系人 |

**列表列说明**：

| 列名 | 说明 |
|------|------|
| 序号 | 行号 |
| 任务标题 | 任务名称，点击进入详情 |

## 5. 执行人工作流——任务反馈

### 5.1 执行人如何查看任务

当任务分配给您（作为执行人）时：
1. 检查 CRM 中的**待办事项**列表——任务会出现在其中。
2. 同时会收到**邮件通知**（如已配置）。
3. 点击任务打开详情视图。

### 5.2 提交任务反馈

1. 打开任务详情视图。
2. 点击**任务反馈**按钮。
3. 在反馈弹窗中填写：

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 完成进度 | 是 | 滑块（0–100%） | 拖动滑块设置当前完成百分比 |
| 通知 | 否 | 复选框 | ☑ 负责人，☑ 抄送人——谁收到本次更新通知 |
| 描述 | 否 | 富文本编辑器 | 进度详情说明；支持格式化（粗体、列表、链接） |
| 附件 | 否 | 文件上传 | 支撑材料（如草稿文件、截图） |

4. 点击**确认**提交。

![任务反馈弹窗——完成进度滑块（54%）、通知复选框与富文本编辑器](../../assets/task-003.jpg)

### 5.3 提交反馈后的变化

- 任务的**进度条**更新为提交的百分比。
- 任务状态变为**"待确认"**。
- 负责人（及所选抄送人）收到通知。
- 反馈条目出现在任务详情页的**任务反馈**时间线中。

## 6. 负责人工作流——确认完成

### 6.1 查看反馈

1. 打开任务详情视图（可从父记录的任务列表或通知中进入）。
2. 在**任务反馈**选项卡中查看执行人的反馈内容。
3. 确认更新的**进度**百分比及附件材料。

### 6.2 确认完成

负责人有**两种操作**，取决于任务是部分完成还是全部完成：

| 操作 | 使用场景 | 结果 |
|------|---------|------|
| **通过** | 执行人提交了部分进度（如完成 60%） | 状态保持**"进行中"**，执行人可以继续工作。已确认的进度百分比被记录。 |
| **完成任务** | 任务已全部完成（100% 进度） | 状态变为**"已完成"**，进度条显示 **100%**。点击"完成任务"按钮后该按钮置灰——任务不可重新打开。 |

> 💡 **提示**：随着执行人多次提交进度更新，负责人可以多次"通过"。只有当整个任务真正完成时，才点击"完成任务"。

### 6.3 不满意时的处理方式

若任务完成情况不达标，请通过活动日志或其他沟通方式与执行人沟通，要求其提交新一轮任务反馈并更新进度。

## 7. 子任务

复杂任务可拆解为**子任务**：

1. 打开父任务的详情视图。
2. 切换至**基本信息**选项卡。
3. 点击**+ 添加子任务**。
4. 填写子任务表单（字段与普通任务相同）。
5. 保存。

子任务遵循与父任务相同的负责人 → 执行人 → 反馈 → 确认工作流。父任务的进度与子任务独立，需通过父任务自己的反馈流程单独更新。

## 8. 任务令

### 8.1 什么是任务令？

**任务令（Task Order）** 是一种正式的任务委派机制，适用于管理者向下属发出明确的工作指令。与普通任务不同，任务令要求执行人在开始工作前必须**明确接收确认**，确保委派双方对任务内容和责任达成共识。

**任务令与普通任务的区别**：

| 对比项 | 普通任务 | 任务令 |
|--------|---------|-------|
| 适用场景 | 日常行动项分配 | 正式工作指令下达 |
| 接收确认 | 不需要 | 必须（执行人点击"接收"） |
| 下达后可否修改 | 可修改 | 执行人接收后不可修改 |
| 创建入口 | 任意详情页 | ACTIVITY → Task Order 或详情页 |
| 审计记录 | 基本日志 | 完整的下达→接收→执行日志 |

### 8.2 任务令生命周期

```
管理者下达任务令
      ↓
  [下达（Issued）]
      ↓
执行人点击"接收任务令"
      ↓
  [已接收（Acknowledged）]
      ↓
执行人开始工作并提交反馈
      ↓
  [执行中（In Progress）]
      ↓
执行人提交 100% 反馈
      ↓
  [待确认（Pending Confirmation）]
      ↓
负责人点击"完成任务"
      ↓
  [已完成（Completed）]
```

### 8.3 创建任务令

**操作路径**：左侧导航 → **ACTIVITY → Task Order** → **+ 新建任务令**
或：任意 CRM 详情页 → 任务面板 → **新建任务令**

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| 任务内容 | 是 | 多行文本 | 工作指令的具体内容 |
| 执行人 | 是 | 用户选择器 | 接受指令并执行工作的人员 |
| 截止日期 | 是 | 日期/时间选择器 | 任务必须完成的时间 |
| 优先级 | 是 | 下拉选择 | 高 / 次要 / 低 |
| 关联记录 | 否 | 关联查找 | 关联的商机、线索、客户或联系人 |
| 说明 | 否 | 多行文本 | 背景说明、执行要求、注意事项 |
| 附件 | 否 | 文件上传 | 参考文件或指导材料 |

点击**下达**后，任务令进入**下达**状态，执行人收到待办通知和邮件。

### 8.4 执行人接收任务令

1. 打开待办事项中的任务令通知，或进入 **ACTIVITY → Task Order** 查看。
2. 阅读任务令内容。
3. 点击**接收任务令**按钮。
4. 任务令状态切换为**已接收**，负责人收到接收通知。

> **重要**：执行人接收任务令后，负责人不可再修改任务令内容（截止日期、任务说明等）。如需变更，须撤销当前任务令并重新下达。

### 8.5 后续执行与确认

接收后，任务令遵循与普通任务相同的**任务反馈 → 负责人确认**流程（见第 5、6 节）。

## 9. 业务规则与流程

### 9.1 角色权限

| 权限项 | 说明 | 普通员工 | 销售管理员 | 管理员 |
|--------|------|:-------:|:--------:|:-----:|
| 任务-新建 | 从 CRM 记录创建任务 | ✓ | ✓ | ✓ |
| 任务-编辑 | 编辑任务详情（截止日期、执行人等） | ✓（自己） | ✓ | ✓ |
| 任务-删除 | 删除任务 | ✓（自己） | ✓ | ✓ |
| 任务-查看全部 | 查看非本人相关的所有任务 | — | ✓ | ✓ |
| 任务-导出 | 导出任务列表 | — | ✓ | ✓ |
| 子任务-新建 | 在现有任务下创建子任务 | ✓ | ✓ | ✓ |
| 任务令-下达 | 下达正式任务令 | — | ✓ | ✓ |
| 任务令-查看全部 | 查看全团队的任务令记录 | — | ✓ | ✓ |

> 实际权限分配以系统后台配置为准；如需调整，请联系系统管理员。

### 9.2 标准任务工作流

```
1. 负责人从详情页（商机、线索等）创建任务
2. 设置截止日期、分配执行人、配置提醒
3. 执行人收到待办事项和/或邮件通知
4. 执行人完成工作，通过任务反馈提交进度百分比
5. 负责人查看反馈
6. 负责人点击"完成任务"→ 任务标记为已完成（100%）
```

### 9.3 角色与职责

| 角色 | 职责 |
|------|------|
| **负责人** | 创建任务、审核执行人反馈、确认完成 |
| **执行人** | 接收任务、完成工作、通过任务反馈提交进度更新 |
| **抄送人** | 仅接收通知；无法编辑或确认任务 |

### 9.4 优先级说明

| 优先级 | 适用场景 |
|--------|----------|
| 高 | 截止时间紧迫或业务影响较大的任务 |
| 次要 | 正常优先级、中等紧迫程度的任务 |
| 低 | 不紧急、可推迟的任务 |

### 9.5 提醒设置最佳实践

- 每个任务至少设置**一条提醒**，确保执行人收到通知。
- 重要任务同时使用**待办事项**和**邮件**两个通知渠道，最大化触达效果。
- 截止时间较长的任务，建议设置多条提醒（如提前 1 天 + 提前 3 小时）。

### 9.6 任务关联规则

每个任务必须关联一条父 CRM 记录。从详情页创建任务时，关联关系自动设置。任务不能在没有父记录的情况下"独立"创建。

## 10. 常见问题与注意事项

**问：我为 Danny 创建了任务，但他说没收到通知，怎么办？**
请确认任务的提醒子表中至少有一行配置了**待办事项**或**邮件**方式。若保存时未添加任何提醒行，则不会发送通知。编辑该任务，添加提醒规则即可。

**问：执行人提交了反馈，但状态仍显示"进行中"，原因是什么？**
状态变为"待确认"需要执行人在任务反馈弹窗中点击**确认**。若状态未变化，请询问执行人是否已点击确认按钮（而非直接关闭弹窗）。

**问：执行人可以修改截止日期或优先级吗？**
不能。截止日期和优先级等任务详情只有**负责人**才能编辑。执行人只能提交反馈。

**问：可以创建不关联任何记录的任务吗？**
不可以。任务必须关联父 CRM 记录。始终从详情页创建任务，系统会自动设置关联关系。

**问：一个任务可以有多少个子任务？**
目前无明确限制。可根据工作需要将复杂任务拆解为任意数量的子任务。

**问：任务创建后可以添加抄送人吗？**
可以。点击任务的**编辑**按钮，更新**抄送人**字段即可。

**问："完成任务"按钮和"通过"按钮有什么区别？**
**通过**：确认当前进度，任务状态保持"进行中"，执行人可继续提交反馈。**完成任务**：将任务标记为 100% 完成并关闭，按钮随即置灰，不可重新打开。

**问：任务令和普通任务应该如何选择？**
日常行动项分配使用普通任务即可。以下场景建议使用任务令：（1）上级向下属正式委派重要工作；（2）需要执行人明确签收以确认责任归属；（3）任务完成后需要留存完整的下达-接收-完成审计记录。

**问：执行人接收任务令后，负责人可以修改任务内容吗？**
不可以。一旦执行人点击"接收任务令"，任务令内容即被锁定，不可修改。如确实需要变更，负责人须撤销现有任务令，重新下达修改后的版本。
