# 付款计划模块

## 概述

付款计划（PS）跟踪从销售订单衍生的应收款项和付款里程碑。位于 **REVENUE** 侧边栏区域下。每个销售订单可有多个付款计划（如预付款、进度款、尾款）。付款计划ID格式：`PP` + `YYYYMMDD` + 序号（如 `PP202604270002`）。

**入口路径**: 侧边栏 → REVENUE → Payment Schedule，或从销售订单详情 → Payment Schedule标签页。

## 业务规则

- 付款计划从SO自动生成（如 50/50 预付款 + 进度款）
- 完成率驱动付款类型可见性 — "Final Payment"显示完成率，其他不显示
- 无付款/发票时：应收 = 未收回 = 未开票 = 订单总金额
- 项目经理在付款计划中更新完成率（0-100%）；达到100%时，系统提醒AM生成PI
- 蓝图流程: SO后 → AM创建形式发票 → 从SO自动填充 → 验证发票金额=SO总价值 → 生成PI PDF

## 跨模块关系

| 关系 | 备注 |
|------|------|
| PS ← 销售订单 | PS列表显示SO ID；PS详情回链到SO |
| PS ← 合同/PO | 汇总行显示"合同"字段（映射到客户PO） |
| PS → 开票明细 | PS有"开票明细(N)"子标签页 |
| PS → 回款明细 | 客户详情显示"已收付款"/"待收款" |
| SO → Payment Schedule(N) | SO详情有Payment Schedule标签页及记录数 |

## 注意事项

1. **里程碑字段未使用** — 里程碑编号、里程碑名称、合同条款在当前数据中显示连字符
2. **完成率不一致** — 仅"Final Payment"类型显示完成百分比；预付款和进度款不显示

### SO创建中的付款计划

创建销售订单时，付款计划作为可折叠区域嵌入：

**里程碑类型**: 下拉选项 "By Products" [V]

**列**:
| 列名 | 类型 | 备注 |
|------|------|------|
| 序号 | 自动 | 行号 |
| 里程碑名称 | 文本输入 | 如 "Installation" |
| 付款类型 | 下拉 | "Down Payment"、"Progress Payment"、"Final Payment" [V] |
| 工作内容 | 文本域 | 占位符"输入" |
| 合同条款 | 文本域 | 占位符"输入" |
| 产品信息 | 文本域 | 按产品类型的收入拆分 |
| 操作 | 链接 | 插入 \| 复制 \| 删除 |

**产品信息拆分逻辑** [V]:
- 显示每个里程碑按产品类别的收入分布
- 示例: 预付款 "Software 10% Hardware 20%"
- 剩余: 尾款 "Software 90% Hardware 80%"
- 各类别百分比分阶段合计为100%

### 选择记录弹窗（来自开票申请）[V]

为开票申请（Milestone类型）选择付款计划时：

**过滤字段**:
- 销售订单ID（下拉）
- 付款类型（文本输入）
- 应收金额（数字输入）
- 应收%（数字输入）
- 付款计划ID（文本输入）

**网格列**:
- 序号（单选）
- 付款计划ID（如 PP202605270004）
- 里程碑名称（如 "Installation"）
- fd_milestone_product（如 "Software 10% Hardware 20%"）
- 工作内容
