# P&L实体 (损益表)

## 命名规则

> **对外（客户/文档）统一叫 P&L**，不叫 PL。PL 只是目录/文件/代码中的缩写。
> - 客户视角：P&L（Profit & Loss，损益表）
> - 代码/文件：`pl.md`、`pl.spec.ts`、`mk_km_ltc_pl.json`（技术缩写保持不变）
> - Wiki 正文：首次出现写全称 "P&L (Profit & Loss)"，后续统一用 P&L

## 概述

**模块**: P&L (损益表) — CRM的核心定价引擎
**父级**: 商机（可通过商机详情 → P&L(n)标签页访问，或侧边栏 → P&L → 创建）
**创建页面**: "损益表创建"
**URL路径**: sys-modeling/app/km-ltc

P&L计算成本、利润率，并在批准后生成报价单。它是定价引擎；报价单是从已批准P&L生成的只读视图。

## 业务规则

1. **"锁定对"架构**: P&L是引擎，报价单是视图。
2. **成本录入**: 每个产品行录入采购单价。
3. **利润率计算**: 利润率% = 预期利润 / 总销售价格 × 100
4. **销售价格 = 成本 + 预期利润**（自动计算）
5. **审批工作流**: 用户提交 → 审批链。被拒绝的P&L需要修改。
6. **版本控制**: 自动生成版本。流程日志跟踪所有变更。
7. **多币种**: 支持MYR及汇率转换。
8. **产品同步到商机**: P&L产品同步到商机页面的"产品"标签页（那里只读）。
9. **专业服务**使用服务主数据（非产品目录）进行基于角色的定价。
10. **循环项目**按行标记，转到专用循环标签页。

### 步骤2：产品行项目（按分类标签页）
分类标签页：**软件** | **硬件** | **专业服务** | **报销** | **其他**

#### 软件部分
- 标签："循环"
- 工具栏："+ 添加行"、"导入"、"更多"、"撤销"
- 列：序号、产品（下拉）、备注、销售价格(RM):
  - 单位列表价格
  - 加价百分比（默认0.00%）
  - 单位加价
- 行操作：插入 | 复制 | 删除（注意：UI中有拼写错误"Delet"）

#### 硬件部分
- 标签："循环"
- 工具栏："+ 添加行"、"列设置"、"批量删除"、"撤销"
- 列：序号、成本价格:
  - 单位成本（换算后）
  - 单位（数量）
  - 总成本
  - 预期利润
  - 利润率(%)

#### 专业服务 — 两级父子层级
- **第1级（父）: 活动描述** — 文本输入（如"项目实施"）
  - 汇总子行的成本/价格
  - 循环? 复选框 — 如勾选，转到"PS-循环"标签页
- **第2级（子）: 资源角色** — 从"服务主数据"查找（如"高级工程师"、"项目经理"）
  - 自动填充日费率和成本
  - 人天数: 数字输入（小数）
  - 公式：**人天数 × 日费率 = 总计**

### 步骤3：财务汇总（全局，自动计算）
| 指标 | 计算 |
|--------|-------------|
| 销售价格总计 | 所有行项目销售价格之和 |
| 成本总计 | 所有行项目成本之和 |
| 预期利润 | 销售价格总计 - 成本总计 |
| 利润率(%) | 预期利润 / 销售价格总计 × 100 |

### 折扣控制
- 折扣字段："0.00%"带开关（启用/蓝色）

### 财务计算澄清 [A]
- **利润率公式**: `预期利润 / 销售价格总计 × 100`（这是毛利率，不是加价）
- **加价公式**: `(加价价格 - 列表价格) / 列表价格 × 100`
- **利润公式**: `销售价格总计 - 成本总计`
- 所有数字自动计算；**测试必须验证每个数字**（视频中明确说明）

### 全局折扣行为 [A]
- **开关开启**: 全局折扣自动应用于所有行项目
- **开关关闭**: 出现单个行项目折扣字段，允许不同产品使用不同折扣
- 这提供灵活性：统一折扣 vs 每产品折扣

### 报销逻辑 [A]
- 报销用于转嫁成本（航班、住宿、出租车）
- 应只有成本（通常无加价），但表单允许销售价格以便向客户加价
- 示例：实际航班成本300，售价400 → 利润100，利润率25%

### 审批工作流条件 [A]
1. 如果**任何行项目利润率 < 目标利润率** → 路由到销售团队主管
2. 如果**所有行项目利润率 ≥ 目标利润率** → 自动批准
3. **关键产品条件**: 如果包含关键产品 → 路由到销售团队主管（尚未配置）

### 版本控制 [A]
- 当P&L提交并批准后，它成为固定版本
- **仅最新P&L版本活跃** — 历史版本被停用
- "复制新"按钮：创建新版本最方便的方式（复制当前所有数据）
- "新建报价单"按钮：直接从已批准P&L创建报价单

### 侧边栏编辑模式（新UI）[A]
- 点击行项目的"编辑" → 侧边栏打开包含所有字段
- 比内联表格编辑更方便
- 字段：产品、加价%、数量、备注和自动计算字段
- 保存后更改立即生效

### 货币切换 [A]
- 表头级别的货币下拉（如USD ↔ MYR）
- 切换货币重新计算所有数字（成本、价格、利润率）
- 货币从商机自动携带但可覆盖

### 产品主数据流 [A]
- 列表价格从产品目录自动携带到P&L

- 目标利润率从产品目录自动携带（在产品详情页可见）
- 货币默认为商机货币

### P&L审批工作流 [V]
来自业务蓝图V2，第28页：
- **触发**: 提交P&L表单进行审批
- **角色**: 销售团队主管、系统逻辑
- **条件**:
  1. 如果利润率 < 目标 → 路由到销售团队主管
  2. 如果利润率 ≥ 目标 → 检查关键产品
  3. 如果包含关键产品 → 路由到销售团队主管
  4. 否则 → 自动批准
- **输出**: P&L状态（已批准/已拒绝）
- 流程图: 开始 → P&L表单提交 → 利润率决策 → 关键产品决策 → 销售团队主管 → 已批准? → 结束

### 业务逻辑说明 [V]
1. **利润率计算**: 系统使用`(利润 / 销售价格) × 100`，即标准**毛利率**(Gross Margin)
2. **多年合同**: 硬件可跨越第1年、第2年（续费）、第3年（续费）
3. **概览表中的年份列**表示多年预测能力
4. **服务**经常有0%利润率（收入=成本，转嫁计费）
5. **报销**分类用于费用回收
6. **全局折扣**启用时自动应用于所有行项目
7. **利润率验证**: 行项目利润率 < 目标时显示红色感叹号图标

## 多用户协作工作流 [D] — 来自"Securemetric CRM_new features.docx"

### 协作流程（DOCX确认）

P&L创建支持进入审批工作流前的**多用户协作**：

![P&L Create - Collaborate Option](../assets/pl-collaborate-001.png)

1. **发起人创建P&L** → 填写表单数据
2. **发起人在流程审批侧边栏点击"协作"**（而非"提交"）
   - 操作单选按钮：`提交` | `协作`（选中）
   - 说明文字：*"提交协作后，表单修改权限将转移给接收方。接收方提交回后，您可以编辑表单并将工作流提交到下一步。"*
3. **选择接收方** → 打开EasyCraft用户选择器弹窗
   ![User Picker Modal](../assets/pl-collaborate-002.png)
   - 弹窗标题："EasyCraft"
   - 标签页：最近联系 / 行政组织 / 群组
   - 搜索：模糊关键词搜索
   - 选择用户 → 确认
4. **表单权限转移给接收方**
   - 接收方在消息中心收到待办事项
   ![Message Center To-do](../assets/pl-collaborate-003.png)
   - 任务标题："请处理eKYC & Digital Identi...的协作任务"
   - 位置：消息中心 → 待办事项 → 未处理
5. **接收方打开P&L → 点击编辑**（右上角铅笔图标）
   ![P&L Details - Edit Button](../assets/pl-details-001.png)
   - 接收方从发起人的版本继续编辑
   - 可修改任何字段，添加/移除行项目
6. **接收方提交回** → 返回给发起人
7. **发起人可以**:
   - 分配给另一个协作者（重复周期）
   - 点击**"提交"**进入审批工作流
   ![P&L Details - Submit Operation](../assets/pl-details-002.png)

### 审批工作流条件（更新DOCX信息）

协作完成且发起人提交后：

1. 如果**任何行项目的利润率不符合目标利润率** → 路由到部门负责人(HOD)
2. 如果**P&L包含任何受监控产品** → 路由到HOD
3. 如果**整个交易的总利润率不符合目标** → 路由到财务团队
4. 如果**所有条件满足** → 工作流结束（自动批准）

### 流程审批侧边栏 — 操作模式

| 模式 | 描述 | 下一步 |
|------|-------------|-----------|
| **提交** | 提交审批工作流 | 根据利润率条件路由到HOD/财务 |
| **协作** | 将编辑权限转移给另一个用户 | 接收方收到待办，可编辑并提交回 |
| **回复** | （查看接收到的P&L时）回复请求者 | 返回上一步 |
