## TC-001 - 线索转化 - 服务团队与活动记录继承验证

| 字段 | 值 |
|------|----|
| **模块** | 线索 |
| **类别** | 数据继承 |
| **角色** | 销售代表 |
| **优先级** | P1 |

### 前置条件

线索已存在，包含 2 名服务团队成员（负责人 + 成员）及 3 条活动记录

### 测试步骤

1. 进入线索详情页
2. 确认服务团队有 2 名成员
3. 确认活动记录有 3 条
4. 点击「转化」启动两步转化向导
5. 第一步（客户）：验证/创建客户，继续
6. 第二步（商机）：确认所有 6 个复制选项默认勾选
   - 复制团队至：客户、联系人、商机
   - 复制活动至：客户、联系人、商机
7. 取消勾选「复制活动至 -> 商机」
8. 完成转化
9. 进入新建客户 -> 检查服务团队
10. 进入新建联系人 -> 检查销售记录标签页
11. 进入新建商机 -> 检查服务团队与活动记录

### 预期结果

1. 客户服务团队包含线索的两名团队成员
2. 联系人销售记录包含线索的全部 3 条活动
3. 商机服务团队包含线索的两名团队成员
4. 缺陷回归：商机活动记录不应包含线索活动（复选框已取消勾选）- 验证是否符合预期
5. 线索状态变更为「已转化」（绿色徽章）
6. 转化记录标签页显示含时间戳的转化历史

9. 进入新建商机 -> 验证财务字段

### 预期结果

1. MYR 金额 = 22,300.00（精确计算：100,000,000 x 0.000223）
2. 加权金额 = 5,575.00（22,300 x 0.25）
3. 商机货币 = IDR
4. 实体反映选定实体（SCMY 或 PTSM）
5. 销售记录字段从线索活动历史自动填充

## TC-006 - 商机阶段推进 - 五阶段销售漏斗与胜率

| 字段 | 值 |
|------|----|
| **模块** | 商机 |
| **类别** | 销售漏斗流程 |
| **角色** | 销售代表 |
| **优先级** | P1 |

### 前置条件

商机处于「资格审查」阶段（胜率25%）

### 测试步骤

1. 进入商机详情
2. 确认当前阶段 = 「资格审查」，胜率徽章25%
3. 点击「推进到下一阶段」
4. 确认阶段变更为「方案/POC」（50%）
5. 确认加权金额重新计算：预估金额 x 50%
6. 再次点击「推进到下一阶段」
7. 确认阶段变更为「价格谈判」（75%）
8. 点击「推进到下一阶段」-> 选择「成交」
9. 确认阶段变更为「成交」（100%）
10. 确认状态徽章变更为「已赢单」（绿色）
11. 尝试从「成交」继续推进 -> 应被阻止

### 预期结果

1. 阶段推进顺序：资格审查(25%) -> 方案/POC(50%) -> 价格谈判(75%) -> 成交(100%)
2. 每次推进重新计算加权金额 = 预估金额 x 胜率
3. 成交后：状态=「已赢单」，漏斗阶段=100%
4. 成交是终止阶段 - 不可继续推进
5. 丢单（0%）也是终止阶段
6. 所有阶段推进均为手动（蓝图规定，无自动推进）

## TC-011 - 损益表财务摘要 - 利润率计算准确性（加价法 vs 毛利率）

| 字段 | 值 |
|------|----|
| **模块** | 损益表 |
| **类别** | 财务计算 |
| **角色** | 销售代表 |
| **优先级** | P1 |

### 前置条件

损益表存在：2个软件产品（定价：5000、3000）和1个硬件产品（成本：2000）

### 测试步骤

1. 进入损益表创建/详情页
2. 添加 2 个软件产品：
   - 产品A：定价=5,000，加价=20% -> 销售价格=6,000
   - 产品B：定价=3,000，加价=10% -> 销售价格=3,300
3. 添加 1 个硬件产品：
   - 单位成本=2,000，预期利润=500 -> 销售价格=2,500
4. 验证财务摘要卡片：
   - 总收入 = 6,000 + 3,300 + 2,500 = 11,800
   - 总成本 = 软件成本 + 2,000
   - 总利润 = 总收入 - 总成本
   - 利润率 % = （总利润 / 总收入）x 100
5. 验证每条明细利润率 = （利润 / 售价）x 100（毛利率公式）
6. 确认当利润率 < 目标利润率时出现红色警告图标

### 预期结果

1. 关键：系统使用毛利率公式（利润/售价）x100
2. 软件：销售价格 = 定价 x（1 + 加价%）
3. 硬件：销售价格 = 成本 + 预期利润
4. 总收入卡片：蓝色文字，所有销售价格之和
5. 总利润卡片：绿色文字（收入 - 成本）
6. 利润率卡片：>= 目标时绿色，< 目标时红色
7. 利润率 < 目标的明细行显示红色感叹号警告图标
8. 所有数字自动计算

## TC-039 - 损益表版本锁定 - 报价单生成与版本对应关系

| 字段 | 值 |
|------|----|
| **模块** | 跨模块 |
| **类别** | 损益表版本控制 |
| **角色** | 销售代表 |
| **优先级** | P1 |

### 前置条件

损益表V1已审批，报价单V1已生成

### 测试步骤

1. 进入损益表详情 -> 确认版本=「V1」
2. 进入报价单详情 -> 确认关联损益表V1
3. 对损益表点击「复制新建」-> 创建损益表V2
4. 修改损益表V2的定价 -> 提交 -> 审批
5. 进入报价单 -> 确认仍关联损益表V1
6. 从损益表V2点击「新建报价单」-> 创建报价单V2
7. 确认报价单V2反映损益表V2的定价
8. 确认报价单V1仍显示损益表V1的定价（版本锁定）
9. 尝试直接编辑报价单V1 -> 应被阻止
10. 确认销售漏斗看板报告中仅包含「有效」损益表版本（V2）

1. 损益表V1->报价单V1，损益表V2->报价单V2（版本对应）
2. 报价单不能直接编辑 - 须修改底层损益表
3. 「复制新建」创建含所有数据的新损益表版本
4. 历史损益表版本被停用
5. 仅「有效」损益表版本数据在销售漏斗看板中汇总
6. 版本锁定防止管道报告中的数据膨胀（蓝图原则1和5）
7. 完整审计追踪：每次版本变更在流程记录中追踪
