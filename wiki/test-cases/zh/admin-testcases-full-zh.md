## TC-003 - 线索队列 - 7 天 SLA 回收倒计时

| 字段 | 值 |
|------|----|
| **模块** | 线索 |
| **类别** | SLA 执行 |
| **角色** | 销售经理 |
| **优先级** | P2 |

### 前置条件

线索存在于未分配队列，5 天前已分配，无跟进活动

### 测试步骤

1. 以销售经理身份登录
2. 进入线索队列配置
3. 确认认领与分配规则 = 「对成员隐藏，管理员可分配」
4. 进入线索列表 -> 按「未分配」状态筛选
5. 找到 5 天前分配的线索
6. 确认「回收倒计时」列显示「2天」（7 - 5 = 2 天剩余）
7. 等待/模拟至倒计时变为「-1天」（逾期）
8. 确认线索自动返回公共池
9. 确认向原分配人发送通知

### 预期结果

1. 回收倒计时准确反映剩余天数
2. 负数（如「-1天」）表示逾期线索
3. 逾期线索自动返回公共池
4. 原分配人收到「回收倒计时」通知
5. 线索不会自动剥夺 - 仅返回公共池（蓝图原则2：提醒优于强制）
6. 该地区任意客户经理均可从公共池认领该线索

## TC-005 - 线索可见性 - 实体隔离与服务团队访问

| 字段 | 值 |
|------|----|
| **模块** | 线索 |
| **类别** | 权限 |
| **角色** | 销售代表 |
| **优先级** | P1 |

### 前置条件

线索-A（实体=SCMY，用户A在服务团队）；线索-B（实体=SMMY，用户B不在服务团队）

### 测试步骤

1. 以用户A（SCMY实体）登录
2. 进入线索列表 -> 筛选「全部」
3. 确认线索-A可见且可编辑
4. 确认线索-B不可见（实体隔离）
5. 以用户B（SMMY实体）登录
6. 进入线索列表
7. 通过直接URL尝试访问线索-A
8. 以管理员身份将用户B以只读权限加入线索-A服务团队
9. 以用户B登录，尝试编辑线索-A字段

### 预期结果

1. 实体隔离：用户A仅可见SCMY线索，用户B仅可见SMMY线索
2. 用户B通过直接URL访问线索-A返回拒绝访问
3. 加入服务团队（只读）后：用户B可查看但不能编辑线索-A
4. 服务团队权限对特定记录覆盖实体隔离
5. 负责人自动分配：创建者自动加入服务团队

## TC-007 - 权限 - 负责人不在服务团队的访问控制（已知缺陷回归）

| 字段 | 值 |
|------|----|
| **模块** | 商机 |
| **类别** | 权限缺陷 |
| **角色** | 销售经理 |
| **优先级** | P1 |

### 前置条件

商机存在，且负责人不在服务团队成员列表中

### 测试步骤

1. 进入商机详情（负责人不在服务团队中）
2. 确认负责人字段显示某用户（如「Nixon」）
3. 打开服务团队侧边栏 -> 确认负责人未列出
4. 以负责人身份尝试在该商机下创建销售订单
5. 以非负责人且不在服务团队的用户身份尝试编辑商机字段
6. 以非负责人且不在服务团队的用户身份尝试创建销售订单

### 预期结果

1. 缺陷：负责人即使不在服务团队中，也能创建销售订单
   - 预期：负责人应自动拥有访问权限或被加入服务团队
   - 实际：负责人绕过子记录创建的服务团队检查
2. 非负责人且不在服务团队的用户不能编辑商机字段（正确）
3. 非负责人且不在服务团队的用户不能创建销售订单（正确）
4. 缺陷严重程度：高 - 权限不一致

## TC-024 - 权限 - 非负责人编辑付款计划（已知缺陷回归）

| 字段 | 值 |
|------|----|
| **模块** | 销售订单 |
| **类别** | 权限缺陷 |
| **角色** | 销售经理 |
| **优先级** | P1 |

### 前置条件

销售订单存在，付款计划已创建，用户「Yuwin」不是负责人

### 测试步骤

1. 以「Yuwin」（非该销售订单负责人）登录
2. 进入销售订单详情 -> 付款计划标签
3. 点击某条付款计划里程碑
4. 尝试编辑付款计划详情
5. 点击「修改完成百分比」-> 尝试修改
6. 以负责人登录 -> 执行相同操作
7. 确认哪个用户可以/不可以编辑

### 预期结果

1. 缺陷：非负责人（Yuwin）即使不是负责人也能编辑付款计划
   - 预期：仅负责人（或明确授权用户）可编辑
   - 实际：任何有销售订单访问权的用户均可编辑付款计划
2. 缺陷严重程度：高 - 财务数据完整性存在风险
3. 负责人可编辑（预期行为）
4. 付款计划含关键财务数据（应收金额、完成百分比）
5. 这与视频16中描述的服务团队权限模型相矛盾

## TC-038 - 数据分片 - 跨实体可见性与公共池

| 字段 | 值 |
|------|----|
| **模块** | 跨模块 |
| **类别** | 实体隔离 |
| **角色** | 销售经理 |
| **优先级** | P1 |

### 前置条件

SCMY实体下存在一个客户，SMMY实体下存在另一个客户

### 测试步骤

1. 以用户A（SCMY实体）登录
2. 进入客户列表 -> 确认仅可见SCMY客户
3. 通过直接URL尝试访问SMMY客户 -> 拒绝访问
4. 进入公共池 -> 确认可见未分配的SCMY客户
5. 确认SMMY公共池客户对SCMY用户不可见
6. 以用户B（SMMY实体）登录
7. 确认镜像行为：SMMY客户可见，SCMY客户不可见
8. 管理员用户：确认可见所有实体记录

### 预期结果

1. 实体隔离：各实体数据互相不可见（蓝图设计原则3）
2. 公共池仅对同一地区的所有客户经理可见
3. 直接URL访问跨实体记录返回拒绝访问
4. 管理员/超级管理员可见所有实体
5. 导出限制保护各实体的敏感联系人数据
6. 多国分片：MY/VN/PH/ID数据分区
